# Go port working notes

- Goal: a complete Go compiler with equivalent behavior, then a measured 10× end-to-end type-checking speedup over the original native tsc-ts implementation.
- Original repository baseline: `d3e96c1`; native build uses locked scriptc 0.3.5 with the repository's speed optimization and detached-exit flags. Node execution is not the performance baseline.
- Starting Go implementation: maintained source fork of the exact compiler ancestor, Microsoft TypeScript-Go `2bd066d87f5bafd315be9f40889d0a60b9e58e0b`. Preserve licensing and distinguish inherited code from new optimizations.
- Target workloads from the supplied screenshots: VS Code, Sentry, TypeORM, tRPC. Screenshots provide no revisions, commands, machine specification, or raw measurements. Independently pinned snapshots must be identified as new measurements, not reproductions of the quoted ratios.
- Benchmark requirements: same sources/options/libs, cold process per sample, warm filesystem cache identified, no incremental result reuse, successful checks and diagnostics parity, alternating execution order, raw samples and toolchain/CPU metadata. No successful speedup claim for failed or skipped work.
- Initial audit: the old benchmark omits native tsc-ts whole-project checking and ignores process failures. A new correctness-gated harness is under development.
- Initial optimization candidates: checker scheduling and duplicated semantic work; profile allocations and GC before changing runtime policy. Full correctness is a constraint; do not remove checks to obtain speedups.
- GitHub Actions CI and release workflows moved to `.github/workflows-disabled/` at user request. Validation runs locally. Commit `3979390` pushed to main. Repository Actions permission also disabled through GitHub API and verified `enabled:false`; no outstanding runs were listed.
- Environment: Linux x86_64, 8 logical CPUs, approximately 39 GiB RAM; Node 24.15.0, npm 11.12.1, Go 1.26.9 installed under `/tmp/tsc-toolchains/go`, clang/lld 18 installed. Standard sandbox networking failed DNS; approved escalated network commands succeed. No environment-status tool or network-policy snapshot is exposed here.
- Toolchain setup: locked npm install completed; scriptc postinstall required `npm rebuild scriptc --foreground-scripts`; pinned upstream compiler and TypeScript corpus downloaded.
- Source checkpoint: `packages/tsc-go` contains the full pinned Go compiler, embedded libraries, original internal tests, npm build/launcher integration, and `TSC_TS_LIB_DIR` compatibility. Initial Go and native tsc-ts builds are still running at this checkpoint; compilation, behavioral validation, and performance are not yet claimed.
- Benchmark harness committed as `59093fd`; five integrity tests pass. All four snapshots/dependencies are fetched. Setup checks using the official TS7 dependency pass for tRPC, TypeORM, and Sentry; VS Code checking is still running. TypeORM needs explicit `module=node20,moduleResolution=node16` compatibility overrides, applied to both compilers. Sentry reference declaration builds are encoded in preparation steps.
- Initial builds completed: original native binary preserved as `packages/tsc-ts/dist/tsc-original` (SHA256 `525c0fe92b231e13ce225687929a606b1d7d47851216cc10d4e2b91dfdcd0bb4`); initial Go `packages/tsc-go/dist/tsc-go-initial` (SHA256 `82162d21b98442d33f6e47eb45381958a8ae0f322c5c6904623ee4f252fdeea2`). Both report version 7.0.2. Go source checkpoint `c6c77d1`.
- All six Go unit suites pass (core, ast, bundled, scanner, compiler, checker). Native parity: 65/65 pass. Existing integration: 11/12 pass; declaration union ordering varies with checker count, matching the TS-only fix in original HEAD `d3e96c1`; porting it is required. API tests pass. Native child-process tests require escalated execution because the sandbox can report EPERM despite child success; those sandbox failures are not compiler failures.
- First quiet-machine benchmarks (5 alternating pairs, one warmup; full input/diagnostic parity) show initial Go slower: TypeORM native 1420.04 ms vs Go 2878.69 ms; tRPC server native 345.89 ms vs Go 765.20 ms. Raw evidence in `benchmarks/results/initial-typeorm-trpc.json`. No speedup achieved yet.
- Exploratory profiles (not benchmark timings; other work was active): `/tmp/tsc-profiles/trpc-initial/24819-{cpu,mem}profile.pb.gz` and `/tmp/tsc-profiles/vscode-initial/27406-{cpu,mem}profile.pb.gz`, using the pinned reference Go binary. tRPC GC background marking ~21% CPU; VS Code pointer-map lookup and checker side-table operations prominent (~16% through LinkStore). Fresh instantiated-symbol ValueSymbolLinks allocation is a concrete hotspot; long-flow memoization is not the first target on these inputs.
- Optional deterministic cost-balanced scheduler implemented behind `TSC_GO_SCHEDULER=balanced`; compiler unit tests pass; default unchanged pending comparative timing and full parity. Initial binary preserved.
- Algorithm audit: final TS has lazy generic member instantiation (`63ae946`, `d7b26e9`, `a0dc2e2`), primitive-to-union relation fast paths (`c9d29b0`), and template instantiation/distribution caches (`b95d9ab`, `7df723f`) absent from the Go ancestor. VS Code profile attributes 7.14% CPU to eager member-table instantiation (overlapping its 12.06% enclosing member resolution); primitive union checks are 1.14% VS Code and 4.47% tRPC. These are opportunity bounds, not predicted savings. Go maps have no stable iteration order, so a lazy-member port must freeze or key keep/clone state, not directly copy TS Map position bitmaps.
- Larger initial benchmarks completed (3 alternating pairs, one warmup): VS Code native 21373.07 ms vs Go 46383.26 ms; Sentry native 14570.59 ms vs Go 42412.11 ms. Both have identical inputs and clean diagnostics. Raw evidence in `benchmarks/results/initial-vscode-sentry.json`. All four initial Go measurements are slower than native tsc-ts.
- Corrected candidate built and preserved as `packages/tsc-go/dist/tsc-go-corrected`, SHA256 `a54000fe92760b45e2cafe12f8bfbf9b0facd3d8d20a540699c1135ab0e51c64`. Combined declaration-order fix, fresh-symbol link allocation, and optional balanced scheduling pass core/compiler/checker Go suites, 13 existing integration tests (including the previously failing declaration-order regression), and 70 native parity comparisons each under default and balanced scheduling; no skips. Shared checker fixture extraction passes the original 15-case checker test.
- Status: next experiments vary candidate checker count and GC settings, with original native baseline defaults preserved and exact arguments/environment recorded. Primitive-union and lazy-member ports remain isolated/unvalidated. 10× target remains unproven.
