# Saturated keyBuilder streaming length: independent review

Reviewed patch db1de850af2817da0bef2d6d1b120f8b6e3da4c1528678373014ff37a50e3551, AUDIT, current direct-writer source and tests. Source-only; no builds/tests/profiles, Go commands, or main edits. No correctness blocker found.

Proof: completed method calls preserve0<=n<=128 and overflow!=nil implies n==128. stream initializes once, copies exactly buf[:old n] before setting n128, and never copies again when an overflow object already exists. Thus each primitive capacity test alone excludes streaming states. Inline exact-fit n128 with nil overflow remains distinct and valid because hash retains its pointer test. There is no new negative or out-of-range sentinel, integer encoding/caller changes, or changed whole-value spill behavior.

Explicit stream at zero copies an empty prefix, then saturates; at partial prefix it copies only written bytes, not uninitialized tail; at full prefix it copies all128 bytes. Later primitive writes always append to the existing stream. Byte/string empty writes still do nothing to payload: full inline remains inline, streaming remains streaming. No duplicate prefix appears on repeated stream calls or repeated hash/continuation. b.n is now intentionally not a logical input-byte count in streaming mode; source inventory found no external production consumers relying on that value. Tests inspect buf[:n] only while overflow==nil.

Reentrancy: xxh3.Write synchronously consumes bytes and has no checker/user callback. The temporary internal state overflow!=nil/n<128 while copying the prefix cannot be observed by supported single-owner calls. Independent recursive builders have separate arrays/hashers. Concurrent mutation or copying an active builder remains unsupported; saturation does not make copying the overflow pointer safe. Small documentation clarification worth considering: calling private stream() even at an empty prefix creates active state, so the no-copy rule should also cover that use before any public write (e.g. 'must not be copied after use'). Current production never copies builders, so this is not a blocker.

The new eight-subcase test directly targets the invariant: zero/partial/full prefix streaming; stable hasher identity; independent full-hash equality before/after empty writes; then byte,uint32,uint64 continuations and final saturated state. It would catch saturation-before-copy, replay, and forgotten routing after a partial prefix. Existing390 width/prefix cases retain coverage for naturally triggered stream transitions. Test checks use existing independent byte/full-hash oracle; they do not replace actual execution. All remain unrun for this draft.

No inlining, allocation, code-size, or speed claim follows. Guard removal is equivalent under the invariant, but actual compiler budget/frame/escape effects need later validation. The invariant must remain documented if stream or alternative writer construction changes.
