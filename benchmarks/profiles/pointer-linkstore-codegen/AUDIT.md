## Actual call boundaries

`Checker.instantiateSymbol` calls the shape-specialized PointerLinkStore.Get at checker.go20673 (instruction0x81a198). `getTypeOfInstantiatedSymbol` also directly calls Get at checker.go16445 (0x8003e9); the originally considered getTypeOfSymbol is only a dispatch wrapper. `newInstantiatedSymbolWithLinks` loads the concrete Symbol/ValueSymbolLinks dictionary and calls shape-specialized New at checker.go20723 (0x81a5c2). No indirect interface dispatch occurs at these boundaries, but neither Get nor New is inlined into these inspected hot callers.

Get (174 text bytes) and New (122) each call slot (218). Get's nonempty hit thus has two explicit store-related call boundaries from the checker, followed by the value load and return. slot preserves the typed key register for equality. The hash helper is inlined in slot: shifts30/27/31, two 64-bit immediate constants, two IMULQ instructions, xor mixing and capacity mask are visible at pointerlinkstore.go25..33. There is no separate pointerLinkHash symbol in the filtered symbol table and no helper call in slot. Linear probing advances index with the same mask. The compiler retains a per-probe bounds check and the source's bounded full-table loop; this audit does not recommend removing either. slot's ordinary successful path contains no calls except its function entry/return; panic and stack-growth paths remain present.

Get/slot successful lookup paths do not write to the table, counters or heap and contain no write barrier. They write ordinary stack spill/prologue state as needed; “read-only” here means shared store state, not zero machine stores. New still probes for the slot before insertAt, including when its caller proves the new symbol absent; this maintains the duplicate replacement behavior. Growth can add a second slot search. No cost or speedup is inferred from static instruction/call counts.

## Typed allocations and barriers

insertAt (396 text bytes) calls Arena[ValueSymbolLinks].New, then updates count only for an empty entry and publishes two typed pointers through an emitted runtime.writeBarrier test/gcWriteBarrier4 sequence. On replacement the new value remains fresh; other returned arena pointers remain valid according to their own live references.

grow (441 bytes) calls runtime.makeslice for the new typed entry backing array, rehashes existing keys with slot, copies each key/value pair through a write-barrier path, then publishes the new slice through gcWriteBarrier2. Rehashing moves table entries, not Symbol or ValueSymbolLinks allocations. Old table backing storage may be reclaimed when no copies retain it; old value arena chunks remain reachable through typed entry pointers.

The inspected Arena[ValueSymbolLinks].New calls runtime.growslice only when a chunk is full, carries the element type descriptor to allocation, publishes its typed backing pointer through gcWriteBarrier2 and returns an interior pointer using the concrete element stride. There is no runtime.newobject per value on the ordinary arena path. Checker.newSymbol also calls its typed arena. The newobject visible in newInstantiatedSymbolWithLinks belongs to the preexisting combined TypeMapper branch, not a new per-link allocation introduced by this store. Writing target/mapper/nameType into the returned links emits the expected GC barriers independently of table publication.

## Lifetime and address-identity assumptions

The table never stores uintptr hashes as ownership roots and never reconstructs a pointer from an integer. Entries retain *ast.Symbol and *ValueSymbolLinks; allocation and entry publication are typed Go operations with compiler-generated barriers. Arena interior pointers keep the allocation containing them alive, including retired chunks no longer retained by the arena's current slice. Caller-held result pointers remain valid across table growth. The source tests explicitly cover retained old chunks and read-only store copies; this audit does not rerun or replace those tests.

One-way uintptr conversion for hashing is distinct from using uintptr as liveness. The actual key remains typed during lookup and in occupied entries. Non-moving heap addresses are nevertheless a semantic requirement: bucket placement derived from the original address becomes stale if a future collector relocates the key, even if typed references are updated correctly. The source documents this dependency at pointerlinkstore.go7; generic pointer identity/equality alone does not make an address hash portable to a moving heap. Compiler-created symbols in this integration are heap/arena allocations; do not generalize this implementation to unstable stack-address hashing or a future moving collector without stable IDs or rehash notification. No runtime.KeepAlive call would repair changed bucket placement.

Copies retain shared entry storage and arena backing slices. Concurrent read-only existing-key Get/TryGet/Has after publication is the stated model; mutations require exclusive ownership, and independent writes through store copies remain unsupported. Misses in Get are mutations. The store remains checker-local, and this integration changes only valueSymbolLinks, not the other link maps.

No new source/codegen correctness blocker found. Generated code demonstrates the intended typed storage and inline hash, while retaining explicit Get/New/slot call boundaries and ordinary allocation/barrier costs. This is implementation evidence only: binary text sizes, synthetic benchmarks and instruction counts do not establish compiler speed or RSS improvement. Whole-workload correctness and controlled Go-to-Go timings remain separate acceptance gates.
