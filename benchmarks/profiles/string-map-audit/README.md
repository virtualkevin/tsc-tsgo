# String-map path audit

This offline audit reuses the retained normal-flag CPU profiles, verifies raw-input hashes against `../normal-map-attribution/inputs.json`, and counts each sample containing a specialized runtime `*_faststr` map access/assignment/deletion entry point once. Attribution goes to the nearest project caller above the innermost matching entry point. Allocation and hash callees are included; generic map operations are excluded even when their keys might be strings. These are CPU-stack samples, not lookup counts, pure hashing cost, wall time or removable runtime.

Observed fractions: tRPC 10.660%, TypeORM 5.629%, VS Code 6.813%, Sentry 10.251%. The largest VS Code and Sentry contributor is getResolvedMember (1.027% and 2.221% of all sampled CPU). Sentry union/intersection property lookup contributes another 1.588%. Small-workload samples are coarse: a 20ms sample is about 1% of tRPC's 1.97s sampled CPU. The full caller lists and example stacks are preserved in report.json.

Source audit: Parser.internIdentifier uses a parser-local map[string]string and returns string text. Symbol.Name and SymbolTable remain strings. Equal text across parser instances therefore does not establish a program-wide identity. Member layouts already share name-position maps across related instantiations; treating each instance as owning a separate name table would overstate savings. Pending-member lookup may recurse through bases and lazily instantiate symbols, so its complete caller cost is not just hashing.

A global name-ID replacement is not justified by this audit alone. It would require domain/lifetime rules for parsed and synthetic names, declaration strings, API queries, multiple checkers, and reused source files. An interner lookup at every semantic lookup can simply add another hash operation. A next useful diagnostic is a checker-local resolved-member census: path category, hit/miss counts, table-size and key-length distributions, with bounded storage and observer controls. It must not retain queried semantic objects or claim unique-name frequency without actually measuring it. This would distinguish small sparse lookup paths from dense shared layouts before choosing a representation.

No production change or new performance measurement. Five analyzer tests cover nested map attribution, allocation callees, inline frames, generic-map exclusion, denominator and parse rejection. Run `PYTHONDONTWRITEBYTECODE=1 python3 test_analyze.py` and `PYTHONDONTWRITEBYTECODE=1 python3 reproduce.py` from this directory. The reproducer checks the committed report exactly and reads the existing raw archive without extraction.
