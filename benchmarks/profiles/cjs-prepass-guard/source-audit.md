# Skip the declaration-emitter CommonJS prepass in non-CommonJS files

Draft against main HEADbd16eabcc331cf483743fd2975da666a845f40c0. Patch `cjs-prepass-guard.patch`, SHA256 `e2932504d35fb117dedfbbe9ee482e5a0e61d4942db27671ac9f32e6c97e5ed2`. Exactly one production control-flow change at packages/tsc-go/internal/transformers/declarations/transform.go348: guard the cjsExportAssignmentVisitor pass with node.CommonJSModuleIndicator!=nil. The adjacent second visitor comment spacing changes only because gofmt realigns it. The second expando prepass and all actual declaration transformation/diagnostic code are untouched. Isolated /tmp source only; gofmt and git apply --check passed. No build/test/performance result exists for the draft.

## Source-level equivalence argument

1. visitSourceFile sets state.currentSourceFile=node, initializes diagnostic state, precalculates declaration visibility, then calls transformSourceFile(node). The proposed predicate therefore tests the same source file as visitCJSExportAssignments currently tests internally. It does not infer mode from extension, module compiler options, noEmit, or a textual module.exports substring.
2. visitCJSExportAssignments at2639 has one semantic action: for JSDeclarationKindModuleExports AND currentSourceFile.CommonJSModuleIndicator!=nil, invoke transformExportAssignment, then possibly update cjsExportAssignment/resultHasScopeMarker/resultHasExternalModuleIndicator. If the indicator is nil, that action is unreachable for every visited node. GetAssignmentDeclarationKind reads syntax/kind/JS flags only; it neither binds nor sets the file's module indicator. The binder is responsible for setting CommonJSModuleIndicator before declaration transforms (binder.go936). No nil-file transition to CommonJS can occur through this visitor's disabled action.
3. For the skipped case, setupDiagnosticContext still currently runs at every node. It saves getSymbolAccessibilityDiagnostic/errorNameNode/suppressNewDiagnosticContexts, may install a diagnostic-selector closure and suppression flag, then its defer restores all three. Selector construction chooses a function but does not ask the resolver for accessibility, append diagnostics, transform declarations or emit an error. Some AST flag reads may populate lazy syntax caches; those are not required earlier than their next read and are not compiler output. No callback consumes the temporary diagnostic context because the only semantic action is disabled. Skipping this balanced temporary state does not erase diagnostics.
4. The remaining work is recursive NodeVisitor.VisitEachChild. In the nil-indicator case each callback returns the traversal of the unchanged node; no transformExportAssignment is called and no replacement/hoisting is requested by this callback. EmitContext's visitor hooks push/pop variable/lexical environments, temporarily mark parameter traversal, and merge only declarations actually hoisted by transformations. With this prepass's semantic action disabled they add no declarations. Variable/function/iteration scopes are balanced; their temporary allocations and flags are not inputs to the next pass. Factory updates on unchanged ordinary parsed children return the original nodes; the prepass result is ignored in transformSourceFile in any case. This proof is for the compiler's bound source-file declaration pipeline, not a promise about arbitrary external NodeVisitor hooks or malformed synthetic trees.
5. The second expressionVisitor pass still runs unconditionally. It is required for TypeScript function expandos (JSDeclarationKindProperty may occur in TS), even when CommonJSModuleIndicator is nil. It reenters the same diagnostic contexts itself, discovers properties and performs all existing semantic actions. For CommonJS files both passes still run in their original order, so module.exports is established before exports.x or nested expando declarations. Late-painted statements, private-name errors, isolatedDeclarations errors and declaration serialization are unchanged.
6. No noEmit shortcut is added. getDeclarationDiagnosticsForFile still invokes the declaration transformer and caches diagnostics normally; only an internally inert preparatory walk is avoided for eligible files.

## Native reference, not correctness oracle

The original native implementation contains this whole-file guard in packages/tsc-ts/src/compiler/transformers/declarations.ts around307: only when file.commonJSModuleIndicator exists does it walk ExpressionWalkerKind.ModuleExports. Its Members walk remains unconditional. Local git -S attributes that guard to13e210c (Add declaration emit to tsc-ts), not a later standalone performance commit. Native also uses a read-only walker, processes only BinaryExpression/CallExpression nodes and enters diagnostic context only around relevant assignments. Those broader differences are intentionally excluded: preserving ancestor suppression and Go EmitContext hook behavior needs a separate proof. Native agreement alone is not acceptance evidence, given the demonstrated JSX diagnostic caching difference elsewhere.
