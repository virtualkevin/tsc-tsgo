# Bounded independent relation-key review

Read-only review of original /tmp/tsc-relation-keys/relation-keys.patch and refreshed /tmp/tsc-relation-keys-current/draft checker files against current main helpers. No main edits, builds, tests, or profiling. No production correctness blocker found.

- Ordinary packing is injective on positive30-bit source/target IDs and two state bits, uses only bits0–61, and cannot overlap fallback bit63. Zero/oversized/future-state values fall back. Identity sorting occurs before detection, and state bits intentionally do not swap, matching legacy behavior.
- Generic keys keep complete legacy128-bit serialization, occurrence-position normalization, constrained-ID handling, depth limit, and target identity. Do not claim exact-hash collision elimination for generic fallback; its equality classes retain the existing full-hash contract.
- Reentrancy: generic detection and getConstraintOfTypeParameter can resolve more types/relations. Source/target/state, hash builder, and constrained return are local; no ID is reserved until serialization completes. The subsequent interner lookup sees any entries created recursively and returns their stable ID. Its own insertion path calls no checker resolver/user callback. Thus no mutable shared hash scratch or stale pre-recursion counter reservation was introduced.
- All four key creators and maybe-stack key containers are converted. Relation.size still counts stored results; probing/interning exceptional keys does not affect the relation complexity budget. Partial maybe-stack commits/decrements and failure/overflow flags remain in unchanged code. Relater recycling resets transient assumptions but preserves checker-local interning. Relations are initialized per checker; no production external key consumers or cross-checker relation sharing were found.
- Current helper compatibility is good by static inspection: relationKeyReference uses newObjectType(ObjectFlagsReference), constraints are deliberately preseeded for the synthetic matrix, pendingAPIChecker binds before querying but does not proactively collect diagnostics, and initial variable statement indexes match the cold API fixture. No uninitialized callback problem found.

## Test assessment

The refreshed draft has seven top-level tests (plus two cold-direction subtests). Boundary and generic equivalence-class matrices cover representative key domains and normalized aliases; the legacy helper is a useful representation oracle, not independent proof of the unchanged generic serializer. Synthetic matrix constraints are warm, correctly complemented by the actual cold recursive-constraint API fixture. That fixture checks cold/warm behavior with fresh checkers in both directions, but does not instrument/prove exact nested getRelationKey reentry counts; the source proof above matters.

The new repeated-failure test warms an actual recursive mismatch via IsTypeAssignableTo, then requires exactly two TS2322 diagnostics at two distinct assignment offsets on repeated diagnostic queries. This is materially stronger than only @ts-expect-error comments, which would accept any diagnostic on the line. It still needs first execution against baseline/current draft before its expected positions are called validated.

MaybeStack test meaningfully checks partial commit/discard, count decrement, replacement size, stable intern IDs, and pooled-relater reset. Its overflow/reliability assertions store and retrieve flags directly; they do NOT exercise actual recursion/complexity overflow generation or cached-overflow diagnostic reporting. Keep this claim narrow. Optional inexpensive extension: seed packed and fallback relation entries, then call recursiveTypeRelatedTo with reporting disabled to assert cached success reliability propagation and cached overflow false return, while checking unchanged size/budget. End-to-end overflow coverage can come from existing pinned conformance; no enormous synthetic exhaustion case is needed for this representation refactor.

## Cost caveat

The relation map changes128-bit keys to64-bit keys, but every exceptional/generic probe now also persists in a checker-owned128-bit→64-bit interner. Probe-only keys survive even when no relation result is committed. This may outweigh narrower result maps; no allocation or performance gain follows from the safety review. Keep existing sampled-profile lag and inclusive-overlap limitations.
