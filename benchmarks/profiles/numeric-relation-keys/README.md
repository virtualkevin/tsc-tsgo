# Numeric relation-key experiment

The archived design and reviews precede application of the candidate. The patch changes all five relation-result maps and transient maybe keys from 128-bit hashes to 64-bit keys. Positive ordinary Type IDs below 2^30 and the two current state bits pack exactly; generic/exceptional keys still use the complete existing hash, interned per checker. The fallback table retains probe-only keys, so narrower result maps do not establish net memory or runtime savings.

Fresh profile bounds are in current-review.md and ../pointer-current/. The earlier initial-design.md contains historical expansion profiles and is not the current cost estimate. Both old and new result maps are pointer-free; this is not removal of per-key GC scanning. Build, validation, code generation and benchmark evidence must be assessed separately; no performance benefit follows from source review.

The scope of focused tests is exact key equivalence/ranges, recursive generic constraints, repeated error positions, and cache/maybe-stack bookkeeping. Directly stored overflow flags are not an end-to-end overflow-generation test. Existing checker ownership remains exclusive; this change does not promise concurrent mutations of one checker are safe.
