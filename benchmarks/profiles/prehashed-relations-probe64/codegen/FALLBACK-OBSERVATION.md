# Fallback likelihood and a separate later observation

The64-probe cap is a defensive bound, not proof of an exceptional event. At75% occupancy ordinary linear probing can form long clusters. The table passes through occupancies above roughly37.5% after growth up to75% before the next growth, and a large cache offers many opportunities for a rare long displacement. A cluster longer than64 is not sufficient by itself: fallback requires the particular insertion to have no empty/equal slot within its first64 probes. But the distinction does not make the event impossible under well-distributed xxh3 bits. There is no current empirical incidence estimate or defensible claim that all real caches remain custom tables.

The fixed threshold becomes less conservative in aggregate as the number of insertions/caches grows. Since fallback is permanent, a single ordinary long-probe event can leave a large relation paying earlier custom allocations plus later runtime-map allocations, losing the intended long-run lookup benefit. The five relations across multiple checker workers may behave differently; aggregate compiler duration cannot identify which fell back. Even every important large cache falling back is plausible enough to measure before attributing a neutral timing to the custom lookup algorithm. This note does not predict that it occurs.

A cheap later UNTIMERED diagnostic variant can observe only the cold useFallback path plus checker completion, without per-get or per-probe counters. In an isolated source copy, preserve pointers identifying the five Relation objects, record reason (insert probe bound / rehash-old / rehash-pending / capacity), original count/capacity, and pending-key probe exhaustion; final reports record relation kind, final count and table-vs-map state. A constant-time event at fallback and a final five-entry summary per checker are sufficient. Do not emit full keys, input paths or every operation; do not add atomics to hot get. Distinguish checker instances and PID; account for main/worker exit paths so os.Exit does not silently bypass reporting. One record emitted synchronously at fallback also avoids losing all evidence if final reporting is bypassed.

Run a preserved input project first (Sentry exposes the largest allocation attribution), then others only if useful. Use the exact candidate source plus archived observation patch, isolated binary/hash, explicit default checker count/runtime controls and same pinned inputs. Bound runtime and preserve partial output on timeout. Label this diagnostic variant as untimed; neither its elapsed time nor memory is valid evidence for the production table. No such instrumentation, build or workload has been executed or added to main.

An even narrower synthetic map-only collision study could show the phenomenon but would not establish real key distribution or cache sizes. Avoid tuning the64-probe threshold from synthetic timing. Any threshold/load change is a separate measured experiment, not a correction to semantic validation.
