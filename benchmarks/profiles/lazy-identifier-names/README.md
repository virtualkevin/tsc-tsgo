## Mechanism

Ordinary parsing returns identifier text without maintaining the per-file canonical-string map. The printer is the only runtime consumer of that map found by repository-wide Go source search; source-file cloning is the other non-parser reference. `SourceFile.IdentifierNames()` now materializes it with a synchronized loader, shared by clones. The internal exported `Identifiers` map field is replaced by the accessor; the printer call site is updated. This is an internal Go source API change, not a claim that arbitrary external code accessing that field remains source-compatible. Compiler CLI/API/emit compatibility must be validated separately.

The loader captures immutable parse options, original text, and script kind, never the pooled parser or original AST. On first demand it replays the original parser with interning enabled and keeps only the resulting map. Replay is necessary to reproduce speculative/error-recovery/JSDoc/top-level-await names that are not necessarily represented in the final AST. The temporary replay AST should become collectible after the returned map is obtained. String contents remain unchanged; no unsafe string mutation is used. Source-file publication precedes reads, and `sync.OnceValue` prevents concurrent or clone-induced duplicate replay. Original parsed ASTs/diagnostics are not modified by replay.

This is demand elimination, not another hash/probe/load/layout tuning of the rejected parser-interner experiment. It may reduce parsing work and retained maps in type checking, but files whose names are queried pay for a second parse. It also gives up eager string canonicalization, which can affect retained string storage and comparison costs. Closure/once overhead and temporary replay memory must be measured. No speedup is assumed, and no isolated mechanism explains the whole native-relative 10× gap.
