# Independent small keyBuilder review

Reviewed patch6291b284b57bc038d06aa5760721cb1bfba75763bf5015bf717ef45275bcc1f6, metadata, current production callers, and pinned local xxh3 v1.1.0 sources. Source-only; no Go commands, tests, builds, or profiles. No production correctness blocker found.

- Direct old hasher access inventory matches patch: primitive writers, indexed access flags, exceptional/generic relation state, and legacy relation test helper. Remaining production creations in checker.go and flow.go use methods only. No builder copies/returns/stores found; flow passes a pointer down one serialization. Documented no-copy-after-write contract is important because overflow pointer copies would alias, unlike the old embedded hasher. Current callers satisfy it.
- Transition copies existing inline bytes into a fresh unseeded streaming hasher once, then appends current data. n never exceeds128, so remaining-capacity arithmetic is safe even on32-bit systems. Large input lengths compare against remaining space without adding lengths and risking int overflow. Empty writes preserve both modes. Repeated hash is nonfinal; the pinned library Sum128 copies accumulator state when finishing long streams, and its initial lazy Reset is semantically consistent with subsequent writes.
- Explicit little-endian4/8-byte encoding matches old writers. int→uint64 preserves sign extension on32-bit and64-bit; TypeId/state/access flags remain32bit, SymbolId/NodeId64bit. String writes preserve arbitrary raw bytes. Node/symbol IDs are still requested at the original write site, before possible later work. No allocations or side effects are deferred to hash().
- Generic constraints may recursively construct other builders, but arrays and overflow objects are local per instance. Short aliases/types and long template/flow content share no global scratch. No hashing cache rules or lookup ordering changed.

Audit correction: current writeFlowCacheKey never returns false after writing a partial key. Recursive left/base failure is propagated before suffix writes; identifier unknown and unsupported nodes also return before writes. Therefore the draft AUDIT's specific example of a long discarded flow key allocating overflow is not reachable today. Future caller changes could introduce that cost, but it should not be stated as current behavior. ID/resolver side effects can still occur in failed references, and remain untouched.

Tests: the independent expected-byte construction plus library streaming/one-shot oracle is appropriate for the changed low-level serialization layer. Boundary matrix covers short/stream transitions, repeated sums and continuation, and byte/string chunking. Alias/type tests cross spill boundary and preserve IDs; template test checks actual grammar text delimiters. New tests are not independent of the pinned hash algorithm itself (nor need they be). The relation test named legacyRelationHash now shares the changed keyBuilder primitives; it still checks key equality classes/grammar, but is not a separate old-implementation byte oracle. Because primitive encoding is independently tested and higher-level generic serialization is unchanged, this is a scope caveat rather than a blocker. If expanding coverage, add max/min platform int values and a real flow-key byte expectation; not necessary to duplicate every unchanged cache serializer.

No-copy contract and escape/performance remain main practical caveats. A long key newly allocates a streaming Hasher; short-path actual stack placement and inlining must be verified after release. The128-byte array is zeroed too, and helper call overhead could negate removed large-frame zeroing. No measured short-key distribution or end-to-end improvement is established by this review.
