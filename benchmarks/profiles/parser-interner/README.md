# Per-file canonical string table prototype

Replaces parser/source-file map[string]string with a shared pointer to a StringInterner. The table retains one string per slot, uses randomized standard-library maphash plus full byte equality, linear probing and a fixed75% maximum load. Empty string membership is tracked separately. Growth preserves the first string header; no global registry or cross-file ownership is introduced. SourceFile.Clone retains the same table pointer, matching the old map-sharing behavior. The only discovered post-parse consumer is printer.IsFileLevelUniqueName, now using Has. This source search is not a complete API/reflection compatibility proof.

Preserved normal profiles attribute191.05MiB of VSCode and85.11MiB of Sentry allocation to parser.internIdentifier. These are sampled cumulative allocations, not live heap, CPU budget or removable wall time. Single-copy slots may reduce map key/value duplication, but linear probes, extra growth rehashing, allocator classes and hash seed variation can offset gains. This is a distinct ownership domain and representation from the rejected mutable SymbolTable experiment; no symbol-table behavior changes.
