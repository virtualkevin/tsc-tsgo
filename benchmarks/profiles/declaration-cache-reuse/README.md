# Reuse completed declaration diagnostics during NoEmit

Staged candidate based on the verified declaration-path census (f3cb4ea): TypeORM and tRPC execute both explicit declaration diagnostics and emitter declaration transforms for the same source identities. No comparable invocation exists in the pinned VS Code/Sentry workloads. This candidate is not a route to 10× by itself and has no measured performance result.

The emitter consults Program's existing per-file completed diagnostic cache only after its usual nil-file, EmitOnlyJs and absent-output-path exclusions, and only under NoEmit with non-forced declaration emission. A hit adds the cached diagnostics through the existing collection, marks EmitSkipped, and returns before constructing the second declaration tree. A miss or a custom EmitHost continues the full transform. Normal output and EmitOnlyForcedDts always construct the output tree. No new cache, checker object sharing or diagnostic omission is introduced.

Source review found the transform's output path affects final triple-slash reference assembly, rather than direct diagnostics; its map path is stored but unused. This observation does not replace regression testing. Risks include resolver side effects, diagnostic identity/order, source ownership across checker pools, API call ordering, late alias marking and unusual declaration serialization failures. Existing completed cache publication supplies the same semantic fact that repeated explicit diagnostic requests already reuse, but emit consumers need separate validation.

The staged Go overlay changes emitter.go and adds focused tests. Test fixtures compare cold emit, explicit diagnostics then emit, repeated no-output emit, diagnostics-producing inferred returns, class declarations and late alias chains; separate cases require normal and forced declaration output after cache population. Full root/services, pinned conformance, CLI/oracle parity, API/emit integration and instrumented checks remain required before any production application or performance timing. Focused normal/race/checkptr tests passed seven records across three top-level tests each. Root passed 21,182 records/250 top-level tests; services passed 219/60; pinned conformance passed 12,789 fully checked, eight partial and 2,118 unsupported cases, zero failures. Normal/race/checkptr CLI parity each passed 80 tests; API/emit integration passed 12. Validation readback verified all required coverage and 14 compressed logs. No promotion.

The first fixture intended to produce an isolated-declaration error used a legal direct literal return and failed its expected-error assertion; all evidence is retained in fixture-failure-01. The corrected parameter-dependent return produces the intended diagnostic. Candidate production logic did not change during this correction.
